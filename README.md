# Лабораторна робота №3: Опрацювання виняткових ситуацій із застосуванням Exception

## Предметна область: Інтернет-магазин (каталог товарів та кошик покупця)

Дана лабораторна робота є логічним розвитком ЛР №1 та ЛР №2. У ній реалізовано надійний захист програми від некоректних даних і помилок користувача за допомогою механізму обробки виключень Java (`try`, `catch`, `finally`, `throw`, `throws`), побудовано власну ієрархію перевірених (*checked*) виключень та впроваджено форматований вивід через `printf` / `String.format`.

---

## 🏛️ Ієрархія класів виключень

Для обробки нештатних ситуацій реалізовано власну ієрархію спадкування виключень:

```
java.lang.Throwable
 └── java.lang.Exception (Checked)
      ├── ShopException (Базове доменне виключення магазину)
      │    ├── InvalidPriceException (Ціна <= 0)
      │    └── InvalidQuantityException (Кількість <= 0)
      │
      └── EmptyNameException (Порожнє текстове поле — незалежна гілка)
```

### 1. Клас `ShopException`
Базовий доменний клас для помилок магазину, наслідує `Exception` (*checked* виключення).  
- **Конструктор:** `ShopException(String message)` — передає повідомлення через `super(message)`.

### 2. Клас `InvalidPriceException` (нащадок `ShopException`)
Збуджується, якщо ціна товару є від'ємною або дорівнює нулю.  
- **Поле:** `private final double invalidPrice` — зберігає некоректне числове значення для діагностики.
- **Методи:** `getInvalidPrice()`.

### 3. Клас `InvalidQuantityException` (нащадок `ShopException`)
Збуджується, якщо кількість одиниць товару <= 0.  
- **Поле:** `private final int invalidQuantity` — зберігає некоректну кількість.
- **Методи:** `getInvalidQuantity()`.

### 4. Клас `EmptyNameException` (нащадок `Exception`)
Навмисно винесений в окрему гілку (не наслідує `ShopException`), що дозволяє продемонструвати обробку різних непов'язаних ієрархій виключень у блоках `catch`.  
- **Поле:** `private final String fieldName` — назва поля, що виявилося порожнім.
- **Методи:** `getFieldName()`.

## 📦 Сутності предметної області

### 1. Клас `Customer` (Клієнт)
- Поля: `name` (String), `phone` (String).
- **Конструктор:** `Customer(String name, String phone) throws EmptyNameException`
  - Перевіряє непорожність імені та номера телефону; при порушенні збуджує `EmptyNameException`.

### 2. Клас `Product` (Товар)
- Поля: `name`, `category`, `price`, `quantity`.
- **Конструктор:** `Product(String name, String category, double price, int quantity) throws EmptyNameException, InvalidPriceException, InvalidQuantityException`
  - Виконує повну валідацію кожного поля перед ініціалізацією.
- **Рефакторинг виводу (`toString`):** Замість простої конкатенації застосовано `String.format` з фіксованою шириною колонок (`%-20s`, `%-12s`, `%9.2f`, `%3d`) для акуратного табличного відображення каталогу.

## 🎯 Реалізований функціонал (усі 3 рівні складності)

### Рівень 1. Базовий
1. **Захищене введення даних з консолі:**
   - Перехоплення `InputMismatchException` при спробі ввести нечислові символи замість кількості або ціни.
   - Застосування `IllegalArgumentException` для перевірки бізнес-обмежень (наприклад, кількість товарів для додавання повинна бути > 0).
2. **Гарантоване звільнення ресурсів (`finally`):**
   - Блок `finally` у методі `main` завжди виконується та закриває об'єкт `Scanner`, незалежно від того, завершилась програма штатно чи аварійно.
3. **Поліморфне перехоплення (`catch (Exception e)`):**
   - Використано як фінальний обробник для захисту від непередбачених помилок з виведенням стеку викликів (`e.printStackTrace()`).

### Рівень 2. Середній
1. **Власні checked-виключення:**
   - Створено класи `ShopException`, `InvalidPriceException`, `InvalidQuantityException`, `EmptyNameException`.
   - Усі класи містять виклик `super(message)` та власні поля збереження помилкових значень.
2. **Оголошення `throws` та збудження `throw new`:**
   - Конструктори `Product` та `Customer` сигналізують про можливі винятки через ключове слово `throws`.
   - При некоректних даних спрацьовує `throw new ...`.
3. **Обробка та відновлення:**
   - При виявленні `EmptyNameException` чи помилкового типу користувачеві виводиться зрозуміле повідомлення, після чого пропонується ввести дані повторно без падіння програми.

### Рівень 3. Високий
1. **Кілька розділів `catch` для одного блоку `try`:**
   - Одночасна обробка конкретних винятків (`InvalidPriceException`), альтернативної гілки (`EmptyNameException`) та базового класу (`ShopException`).
2. **Поліморфне перехоплення базовим класом `ShopException`:**
   - Виключення `InvalidQuantityException` не має персонального catch-блоку в циклі зчитування, а перехоплюється своїм суперкласом `ShopException`, демонструючи принцип заміщення.
3. **Механізм повторного збудження (Re-throw):**
   - У блоці введення товару критична помилка ціни (`InvalidPriceException`) спочатку логується (`[LOG] Помилка ціни товару (re-throw)`), після чого збуджується повторно за допомогою `throw e;`.
   - Повторно збуджене виключення перехоплюється зовнішнім блоком `catch (ShopException e)` у методі `main`, коректно завершуючи виконання програми зі збереженням виклику блоку `finally`.

## 🚀 Інструкція запуску

### Швидкий запуск через `run.bat` (Windows)
Двічі клацніть файл `run.bat` або запустіть у терміналі:
```cmd
run.bat
```

### Запуск вручну через консоль
```powershell
chcp 65001 > nul
javac -encoding UTF-8 *.java
java -Dfile.encoding=UTF-8 Main
```
