# Лабораторна робота №3: Опрацювання виняткових ситуацій (Exception)

## Предметна область: Інтернет-магазин (каталог товарів та кошик покупця)

Робота є логічним продовженням ЛР №1 та ЛР №2. У цій лабораторній роботі реалізовано обробку помилок і нештатних ситуацій за допомогою механізму виключень у Java (`try`, `catch`, `finally`, `throw`, `throws`), побудовано власну ієрархію перевірених (*checked*) винятків та додано форматований вивід через `String.format` / `printf`.

---

## 🏛️ Ієрархія виключень

У проєкті реалізовано власну ієрархію виключень:

```text
java.lang.Exception (Checked)
    ├── ShopException (базовий клас помилок інтернет-магазину)
    │       ├── InvalidPriceException (ціна <= 0, зберігає invalidPrice)
    │       └── InvalidQuantityException (кількість <= 0, зберігає invalidQuantity)
    │
    └── EmptyNameException (порожнє текстове поле — незалежна гілка ієрархії)
```

1. **`ShopException`** — базовий клас для доменних помилок магазину (`extends Exception`).
2. **`InvalidPriceException`** — наслідує `ShopException`, сигналізує про некоректну ціну товару (`price <= 0`), зберігає `invalidPrice`.
3. **`InvalidQuantityException`** — наслідує `ShopException`, сигналізує про некоректну кількість (`quantity <= 0`), зберігає `invalidQuantity`.
4. **`EmptyNameException`** — наслідує безпосередньо `Exception` (винесений в окрему гілку від `ShopException`), сигналізує про порожні текстові поля (ім'я, телефон, назва), зберігає `fieldName`.

## 🎯 Реалізовані рівні складності

### Рівень 1. Базовий
- **Безпечне введення чисел:** обробка `NumberFormatException` при спробі ввести нечислові дані (замість аварійного падіння виводиться попередження і пропонується повторне введення).
- **Перевірка меж:** генерація `IllegalArgumentException` для перевірки кількості товарів та бюджетного ліміту (`> 0`).
- **Блок `finally`:** гарантовано закриває `Scanner` при завершенні програми.
- **`catch (Exception e)`:** фінальне перехоплення для захисту від непередбачених помилок.

### Рівень 2. Середній
- **Власні checked-виключення:** `ShopException`, `InvalidPriceException`, `InvalidQuantityException`, `EmptyNameException`.
- **Конструктори сутностей:**
  - `Customer(name, phone) throws EmptyNameException` — перевіряє непорожність полів.
  - `Product(name, category, price, quantity) throws EmptyNameException, InvalidPriceException, InvalidQuantityException` — валідує всі поля об'єкта.
- **Відновлення роботи:** програма не завершується аварійно при введенні некоректних даних, а повідомляє про помилку та дозволяє користувачеві ввести дані повторно.

### Рівень 3. Високий
- **Кілька блоків `catch`:** один блок `try` містить розділи `catch` для `NumberFormatException`, `InvalidPriceException`, `EmptyNameException`, `ShopException`.
- **Поліморфний `catch (ShopException e)`:** помилка кількості товару (`InvalidQuantityException`) не має окремого catch-блоку, а перехоплюється своїм суперкласом `ShopException`.
- **Механізм Re-throw:** метод `createProduct(...)` перехоплює помилку ціни (`InvalidPriceException`), виконує аудит/логування (`[ЛОГ/АУДИТ]: Спроба створення товару з неприпустимою ціною...`), після чого повторно збуджує виняток (`throw e;`) для його обробки на рівні інтерфейсу користувача.

## 📋 Форматований вивід (printf / String.format)

За зауваженням викладача реалізовано акуратне вирівнювання:
- У методі `Product.toString()` використано `String.format` із фіксованою шириною колонок (`%-15s`, `%-12s`, `%8.2f`, `%3d`).
- У `Main.java` для підсумкових рядків застосовано `System.out.printf`.
